# InferGraph 需求文档

基于 Roboflow Inference 开源 fork 的离线化、自建 Registry 与 Build 复刻。

> 调研基准：`本仓库`（fork：`muzhix/inference`，上游：`roboflow/inference`，含 v1.3.7 相关 offline 能力）  
> 文档性质：需求整理与现状调研结论，非实现方案详设  
> 对外品牌：**InferGraph**

---

## 1. 背景与动机

Roboflow Inference / Workflows 的整体设计（本地推理服务、Workflow 执行引擎、Block 生态、协议化模型包）评价很高，希望在开源 fork 上继续使用这套体系。

实际使用中长期困扰的三个问题：


| #   | 痛点                     | 现状结论（调研）                                                                                             |
| --- | ---------------------- | ---------------------------------------------------------------------------------------------------- |
| 1   | 可视化拖拽 Build 不开源        | **属实**。本仓仅有 `/build` iframe 壳 + 本地 JSON API；UI 默认来自 `BUILDER_ORIGIN=https://app.roboflow.com`        |
| 2   | Inference 是否支持 offline | **上游已实现**（见 §2）。`OFFLINE_MODE=True` + 预热 cache 可 air-gapped 运行；仍默认依赖 Roboflow 云做「首次下载 / 在线 registry」 |
| 3   | 强依赖云端 Roboflow 服务与品牌标识 | **属实且深度耦合**。API、模型下载、workflow 拉取、telemetry、Builder UI、OpenAPI 元信息等均指向 Roboflow                       |


目标不是另起炉灶，而是：以 **InferGraph** 为产品品牌，**保留 Roboflow 兼容协议与 Workflow 引擎**，切断云端与品牌依赖，补齐自建 Registry 与开源 Build。

## 2. Offline 能力核实（对「issue 里有 offline」的确认）



### 2.1 结论

**已证实：上游开源仓库已合入完整的** `OFFLINE_MODE` **air-gapped 路径，并非仅停留在讨论。**


| 证据                                                                          | 说明                                                                                                                                                                                  |
| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [PR #2263](https://github.com/roboflow/inference/pull/2263)                 | *Add OFFLINE_MODE and offline cache fallback for air-gapped deployments*（已合并）                                                                                                       |
| [PR #2710](https://github.com/roboflow/inference/pull/2710)                 | *Feat/offline mode fixes*，加固 online/offline 加载与 cache 鉴权行为（已合并）                                                                                                                     |
| [Release v1.3.7](https://github.com/roboflow/inference/releases/tag/v1.3.7) | 正式宣布 `OFFLINE_MODE`：warm cache → 重启并设 `OFFLINE_MODE=True` → 无 API key、无内置 Roboflow API 调用                                                                                           |
| 本仓代码                                                                        | `inference/core/env.py`、`cache/air_gapped.py`、`workflows/offline.py`、相关单测与环境变量文档均已存在                                                                                                |
| 官方文档                                                                        | [Enterprise Offline Mode](https://docs.roboflow.com/deploy/enterprise-deployment/offline-mode)；本仓 `docs/using_inference/offline_weights_download.md` 区分「缓存权重（仍可连网做 billing）」与「完全断网」 |




### 2.2 官方支持的离线流程（现状能力）

```
[在线阶段] 挂载持久 MODEL_CACHE_DIR
    → 用 API key 预热模型 / Workflow 到 cache
    → （可选）拷贝整个 cache 到目标环境

[离线阶段] 同一 cache + OFFLINE_MODE=True + 无 API key
    → 禁止内置 Roboflow API / artifact 下载 / telemetry / remote step 等
    → 仅从受信任本地 cache 加载
```



### 2.3 现状能力边界（与本项目目标的差距）


| 已具备                                     | 仍不满足本项目目标                             |
| --------------------------------------- | ------------------------------------- |
| 预热后完全断网推理                               | 冷启动且 cache 缺失时失败（设计如此）                |
| 阻断内置 Roboflow HTTP、URL 读图、remote step 等 | 模型「注册 / 首次获取」仍默认走 Roboflow 云          |
| Workflow `workspace=local` 本地文件存储       | Builder **前端**仍托管在 `app.roboflow.com` |
| HF / Ultralytics 等依赖库 offline 环境变量自动设置  | Secure Gateway 是「受控出网」，不是「无云」         |
| telemetry / metrics 在 offline 下关闭       | 代码与默认配置中大量 Roboflow 品牌 / 默认 URL       |
| 手动分发整个 warm cache 目录可行                  | 任意丢一个权重文件不够，必须符合协议包格式                 |


**需求解读：** 现有 `OFFLINE_MODE` 是「云端 warm 后的断网运行」；InferGraph 要的是「**无 Roboflow 云参与的端到端离线**」——包括模型入库、registry、Build、推理。

---



## 3. 意图理解（一句话）

在 `roboflow/inference` 开源代码基础上，打造 **InferGraph**：

> **协议兼容 Roboflow、运行时完全离线、模型与 Workflow 完全自建、可视化 Build 完整可用、无 Roboflow 云与品牌依赖** 的本地 Inference / Workflows 平台。

保留：Workflow 执行引擎、Block 体系、Roboflow 兼容模型包 / cache / workflow 协议、HTTP 推理 API 形态。  
替换：云端 Model Registry → InferGraph Registry；云端 Builder → InferGraph Build；品牌与遥测默认项。

| 议题            | 决策                                                                                         |
| ------------- | ------------------------------------------------------------------------------------------ |

## 5. 双 Cache 布局说明与建议

上游同时存在两套磁盘布局，同属 Roboflow 协议生态，但**目录形态不同**。

### 5.1 Traditional（旧 ORT / legacy cache）

典型路径：`$MODEL_CACHE_DIR/{dataset}/{version}/`（或 slug 化目录）

```
my-project/3/
├── model_type.json      # {"project_task_type","model_type","model_id",...}
├── weights.onnx
├── environment.json     # preprocessing、CLASS_MAP 等
├── class_names.txt      # 可选
└── keypoints_metadata.json  # keypoints 模型需要
```


| 优点                    | 缺点                                 |
| --------------------- | ---------------------------------- |
| 结构直观，人手拼包相对容易         | 偏旧栈（ORT `/ort/{model_id}` 下载路径）    |
| 与早期文档 / 大量存量 cache 一致 | metadata 较薄，offline 信任/兼容校验弱于新格式   |
|                       | 对 `.pt` / TensorRT / 多文件包、依赖哈希支持弱  |
|                       | 路径与 model_id 归属规则历史上有多套兼容分支，扫描逻辑复杂 |




### 5.2 inference-models（新包格式 / `models-cache`）

`inference-models` **不是外部无关项目**，而是本仓子包 `inference_models/`：新一代模型加载、weights provider、offline manifest 所在栈（`USE_INFERENCE_MODELS=True` 时走此路径）。

平台训练导出的「Roboflow model package」文档形态通常是：

```
model_package/
├── model_config.json       # 元数据；落入 cache 后带 offline_manifest_version（当前为 4）
├── weights.pt|onnx|engine
├── class_names.txt
└── inference_config.json   # 预处理 / 网络输入 / NMS 等运行时行为
```

落在 Inference 服务器 cache 中时，一般在：

```
$MODEL_CACHE_DIR/models-cache/{slug-of-model-id}/{opaque}/
├── model_config.json       # dump_model_config_for_offline_use 写入
├── weights.*
├── class_names.txt
└── inference_config.json   # 若包内有
```

`model_config.json` 除 architecture / task_type / model_id 外，还包含 `package_artifacts`、`trusted_source`、`offline_compatibility_hash` 等，供 air-gapped 校验。


| 优点                                                          | 缺点                               |
| ----------------------------------------------------------- | -------------------------------- |
| 上游演进主路径；offline 契约更完整                                       | 目录为 slug，不如 `dataset/version` 直观 |
| 支持多种权重后端与 `inference_config.json`                           | 手工拼包要写对 manifest 字段              |
| 与平台导出包、新 weights provider 对齐                                | 双栈并存时扫描/归属逻辑更重                   |
| 已有 `dump_model_config_for_offline_use` 可生成 offline manifest |                                  |




### 5.3 转换 / 导入工具（需求）

**可以且应做。** InferGraph Registry（`inferegistry/`）需提供：


| 工具能力                    | 作用                                                                                                          |
| ----------------------- | ----------------------------------------------------------------------------------------------------------- |
| `pack`                  | 权重 + 类别 + task/architecture（+ 可选 inference_config）→ 生成 **inference-models** 合规包，写入 cache 并注册到 HTTP Registry |
| `import-roboflow-cache` | 导入官方 warm 的 traditional 或 `models-cache` 目录 / 平台导出包（**兼容 Roboflow**）                                        |
| `import-workflow`       | 导入 Roboflow workflow JSON 到本地 `workflow/local`（或 registry 侧存储）                                              |
| `convert`（可选）           | traditional → inference-models；用于消化旧 cache                                                                  |


参考实现：`inference_models/.../auto_loaders/core.py` 的 `dump_model_config_for_offline_use`。

### 5.4 InferGraph Cache 策略（已决）


| 维度          | 决策                                                            |
| ----------- | ------------------------------------------------------------- |
| **新模型写入**   | 只写 **inference-models**（`models-cache` + `model_config.json`） |
| **读取 / 迁移** | **继续读 traditional**，保证官方旧 cache 可导入                           |
| **文档对外**    | 只教用户一种「InferGraph 模型包」（即 inference-models / 平台包结构）            |
| **双栈代码**    | 短期保留双读；用转换工具消化 traditional；中期再评估是否删除 traditional 写路径          |

## 6. Enterprise 许可说明（必须避开什么）

根目录 `LICENSE` 写明：

- 仓库主体适用 **Apache 2.0**（`LICENSE.core`）——**可改、可分发**（遵守 Apache 条款与 NOTICE）。
- 以下目录适用 **Roboflow Enterprise License**（`inference/enterprise/LICENSE.txt`），**不是** Apache：
  - `inference/enterprise/`
  - `inference_cli/lib/enterprise/`
- `inference/models/` 下部分模型另有各自许可证（如部分 YOLO 系列 AGPL 等），与 Enterprise 目录是另一类问题。

Enterprise License 要点（白话）：

- **生产使用**需要单独的 Roboflow Enterprise 协议。
- 允许为开发/测试修改，但修改/补丁权利声明偏向 Roboflow，且**禁止**在无企业许可下复制、合并、发布、分发、出售该 Enterprise Software。
- 因此：**只在开源（Apache）代码上改 InferGraph，一般不触碰 Enterprise 许可**；一旦 import、改写、打包进发行版 `inference/enterprise/` 内容，就可能违规。

**InferGraph 必须避开的能力（目录内现有内容举例）：**


| 类别                     | 示例                                                                     |
| ---------------------- | ---------------------------------------------------------------------- |
| 工业 sink blocks         | MQTT / OPC / PLC / Modbus / EtherNet/IP / Microsoft SQL / Event Writer |
| 并行推理企业栈                | `inference/enterprise/parallel/`（Celery 等）                             |
| Stream management 企业组件 | `inference/enterprise/stream_management/`                              |
| 企业 Helm chart          | `inference/enterprise/helm-chart/`                                     |


**策略：** 发行版与默认加载路径不包含上述目录；若未来需要同类能力，在 Apache 代码树上**独立重写**并自有许可，不从 `enterprise/` 拷贝。

另：部分开源模型权重/适配代码本身是 AGPL 等——分发二进制时需单独合规审查，与「是否改了 enterprise」无关。

## 7. 需求整理



### 7.1 R1 — 完全离线执行（硬约束）

**目标：** 运行时零依赖任何 Roboflow 云端服务（含 Secure Gateway 代理到 Roboflow 的路径）。

**必须：**

1. 默认或以一等公民配置启用「无云」模式（可基于现有 `OFFLINE_MODE`，但语义升级为「无 Roboflow 后端」）。
2. 启动与推理路径不得请求：
  - `api.roboflow.com` / `.one`
  - `*.roboflow.com` hosted 推理端点
  - usage / metrics / version check / Active Learning / dataset upload 等
3. Workflow remote / Modal / 公网 STUN-TURN 等云执行路径默认禁用或移除。
4. Cache miss 时只查询 **InferGraph Registry**（`inferegistry`），永不回落 Roboflow。
5. 自定义 Block / 用户代码若自行联网，不在本约束内，但文档需声明「OS 层隔离才是硬 air-gap」。

**验收：**

- 断网环境下，仅凭本地 cache + InferGraph Registry + 本地 workflow，完成模型推理与 Workflow 运行。
- 抓包 / 防火墙拒绝外网时，内置代码路径无失败重试打到 Roboflow 域名。



### 7.2 R2 — Cache 手动投放 / 工具化导入并可正常推理

**目标：** 无需登录 Roboflow，即可将符合协议的模型包放入 cache（或经 Registry 分发），服务能加载并推理。

**必须：**

1. 对外文档只描述 **InferGraph 模型包**（inference-models 结构）。
2. 运行时读路径兼容 traditional（迁移用）。
3. 提供 `pack` / `import-roboflow-cache`（见 §5.3）。
4. Offline / 无云模式下，cache hit 不要求 API key。
5. 支持整体目录拷贝分发。

**非目标：** 无 metadata 的裸权重「魔法加载」（除非 `pack` 补齐 metadata）。

**验收：**

- 用 `pack` 或手工按文档组装检测模型 → InferGraph / HTTP infer / Workflow 模型步均可跑通。
- 导入一份官方 Roboflow cache 后，断网、无 API key 可推理。



### 7.3 R3 — InferGraph Model Registry（独立 HTTP 服务）

**目标：** 用 `inferegistry/` 中的独立 HTTP 服务替代 `api.roboflow.com` 的模型元数据与权重分发，**协议字段 / 包格式保持 Roboflow 兼容**。

代码位置：与 `inference/` 同级的 `inferegistry/`。

#### 7.3.1 现状映射逻辑（调研摘要）

入口大致为：`RoboflowModelRegistry` → `get_model_type`（`inference/core/registries/roboflow.py`）：

1. Alias 展开（如 `yolov8n-640` → `coco/3`）
2. 本地目录包 / pipeline id / `GENERIC_MODELS` 硬编码
3. （可选）API key 访问校验
4. 读本地 cache metadata（`model_type.json` / `model_config.json`）
5. **Cache miss → 云端**（`/ort/...`、`/getWeights`、`/models/v1/external/stat`）
6. `(task_type, model_type)` → 实现类（`ROBOFLOW_MODEL_TYPES`）

复杂性主要来自：双栈 cache、云端鉴权、Secure Gateway、slug 兼容、企业白名单等——**对 InferGraph 并非全部必要**。

#### 7.3.2 简化原则


| 保留（必要）                                   | 可简化 / 外置 / 删除                             |
| ---------------------------------------- | ----------------------------------------- |
| `model_id` → `(task_type, architecture)` | 云端 miss 拉取与 API key 工作区解析                 |
| `(task_type, architecture)` → 加载器类       | Secure Gateway / credits / service_secret |
| 本地 manifest 查找与校验                        | 与 Roboflow 计费、租约 expiration 相关逻辑          |
| 可选：精简 alias 表（常用基础模型）                    | 双份 SDK alias 强同步（可收敛为单表）                  |
| 协议字段兼容（便于复用加载器）                          | Universe / hosted URL 默认值                 |




#### 7.3.3 功能需求

1. **HTTP Registry**：按 model_id 返回与现有加载器兼容的元数据（对齐 `external-model-metadata-v1` / `model_config.json` 等）。
2. **权重分发**：Registry 或受控本地/HTTP；**禁止**默认回落 Roboflow CDN/S3。
3. **注册 API / CLI**：注册、列表、删除、校验；含 §5.3 的 pack/import。
4. **与 Workflow / Build 集成**：模型枚举改为读 InferGraph Registry + cache。
5. **Inference 侧配置**：原 `API_BASE_URL` / weights provider 指向 `inferegistry`，无云 fallback；环境变量逐步改为 InferGraph 前缀。

**验收：**

- 新模型只通过 InferGraph Registry + cache 导入，全程不接触 Roboflow。
- 现有 Workflow 中引用 `model_id` 的 block 仍可工作（协议层兼容）。
- 可导入 Roboflow 导出的 cache/workflow。



### 7.4 R4 — InferGraph Build（可视化拖拽，复刻 Roboflow Build）

**目标：** 开源实现与 Roboflow Build 对等的可视化 Workflow 构建体验。

**技术栈（已决）：** React + shadcn/ui + React Flow；可先嵌入现有 iframe 壳（`postMessage` + `serverUrl`），再渐进替换为原生挂载。

#### 7.4.1 本仓已具备（复刻基础）


| 能力                             | 位置 / 接口                                                                    |
| ------------------------------ | -------------------------------------------------------------------------- |
| Workflow 执行引擎 / 编译器            | `inference/core/workflows/execution_engine/`                               |
| Core blocks                    | `inference/core/workflows/core_steps/`                                     |
| Blocks schema / air-gapped 元数据 | `GET /workflows/blocks/describe?air_gapped=true`                           |
| Definition JSON Schema         | `GET /workflows/definition/schema`                                         |
| 校验 / 运行 / 动态输出                 | `/workflows/validate`、`/workflows/run`、`/workflows/blocks/dynamic_outputs` |
| 本地 Workflow CRUD               | `/build/api`、`/build/api/{id}`（落盘 `$MODEL_CACHE_DIR/workflow/local/`）      |
| 本地模型列表                         | `/build/api/models`                                                        |
| iframe 壳                       | `builder/editor.html`（当前嵌入云端 UI，将改为 InferGraph Build）                      |




#### 7.4.2 必须实现的产品能力

1. **画布编辑：** 拖拽添加 Block、连线、配置参数、删除/复制（React Flow）。
2. **Schema 驱动：** 以 `/workflows/blocks/describe` 为唯一真相源渲染表单与端口类型（shadcn/ui）。
3. **校验与试跑：** 调用本地 validate/run；错误在画布/面板可读展示。
4. **持久化：** 默认本地存储（兼容现有 `workflow/local`）；支持导入 Roboflow workflow JSON。
5. **模型选择：** 对接 InferGraph Registry / cache。
6. **Air-gapped 感知：** 对 `air_gapped_info.available=false` 的 block 禁用或明确标注。
7. **去云嵌入：** `BUILDER_ORIGIN` 指向 InferGraph Build；移除 `app.roboflow.com`。
8. **去品牌：** 产品名 InferGraph；OpenAPI / UI 无 Roboflow 营销标识。

**非目标（可二期）：**

- 100% 像素级复刻 Roboflow 商业 UI。
- Universe 模板市场、云协作、数据集标注闭环。
- Enterprise 专有 blocks（见 §6）。

**验收：**

- 仅用 InferGraph Build，从空白画布做出含模型推理 + 可视化的 Workflow，保存后断网可重复运行。
- 不加载任何 `*.roboflow.com` 前端资源。



### 7.5 R5 — 移除云依赖与 Roboflow 标识（横切）

**目标：** 代码、默认配置、对外表面呈现 **InferGraph**，不再依赖或暗示 Roboflow 云服务。

**范围（优先级从高到低）：**

1. **运行时默认 URL / Header / 桶名**（逐步去除 `ROBOFLOW_`*、`X-Roboflow-*` 等）
2. **OpenAPI / Landing / Builder** 品牌与联系信息 → InferGraph
3. **直连 Roboflow 的 sink blocks**（upload、monitoring、vision events 等）：删除、禁用，或改为可选插件且默认关闭
4. **文档与主题站** CDN / Universe 链接（可后置）
5. **命名策略：**
  - **协议层**：保留 Roboflow-compatible 字段名 / 包格式（兼容导入）
  - **产品层**：InferGraph；用户可见面去掉 Roboflow 营销标识
  - **代码 / 环境变量**：逐步去 `ROBOFLOW_`* 前缀

**验收：**

- 主要用户可见表面为 InferGraph；协议兼容说明仅出现在开发者文档。

## 11. 成功定义（总验收）

同时满足以下条件即视为 InferGraph 主线完成：

1. **断网 + 无 Roboflow 账号**，可经 InferGraph Registry 注册/导入模型、用 InferGraph Build 编排 Workflow、执行推理。
2. **Cache 手动投放或** `pack` 符合 InferGraph 模型包即可加载；官方 Roboflow cache/workflow 可导入。
3. `inferegistry` **HTTP 服务** 替代云端模型解析与分发；映射逻辑按最小必要集简化；运行时永不回落 Roboflow。
4. **InferGraph Build**（React + shadcn/ui + React Flow）可完成主流可视化编排，不加载 Roboflow 云端前端。
5. **默认部署面**为 InferGraph 品牌；逐步去除 `ROBOFLOW_`*；底层保持 Roboflow 兼容协议。
6. **发行物不含** `inference/enterprise/` 企业许可代码。
